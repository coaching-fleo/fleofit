# Scarpe da corsa — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Una pagina `/scarpe` con il catalogo curato dai coach e le scarpe di ogni atleta, con i km di ogni scarpa calcolati dagli allenamenti completati (Garmin se c'è, altrimenti stima).

**Architecture:** Tre tabelle additive (`scarpe_catalogo`, `scarpe_atleta`, `scarpe_uso`) che salvano solo il legame allenamento → scarpa; i km si calcolano ogni volta in una funzione pura (`kmScarpe.js`). Un modulo d'accesso (`scarpeDb.js`) nasconde le colonne alle schermate; le schermate sono pigre e si nascondono se le tabelle non rispondono.

**Tech Stack:** React 19, Vite 8, Tailwind 4 (token `@theme`), Supabase JS, Vitest + jsdom (`fintoSupabase`, `montaPagina`).

**Spec:** `docs/superpowers/specs/2026-11-02-scarpe-design.md` — chi esegue legge entrambi.

## Global Constraints

- 🔒 La migrazione si **scrive** e non si applica: serve il sì esplicito del committente (CLAUDE.md §0-bis). Nessun comando verso il database vero.
- Si lavora su `app`; commit con file **per nome**, mai `git add -A`/`.`; nessun push.
- Interfaccia e commenti in **italiano**; nomi misti come nei file vicini.
- Colori solo dai token (`bg-brand`, `text-running`, …); niente palette nuova. Barra: neutra → giallo brand da 80% → `red-500` da 100%.
- Mai `alert()`/`confirm()`: `CustomAlert`/`CustomConfirm`. Ogni modale/foglio con `createPortal(…, document.body)`; la X ha `aria-label="Chiudi"` (tasto indietro Android).
- Nessun numero inventato: km sconosciuto = «—», mai 0.
- Soglia di base **700** km; stato `quasi` da **80%**, `oltre` da **100%**.
- `MINUTI_PER_KM` = **6**, una costante sola (esportata da `statistiche.js`).
- Ripetute **solo** via `partiRipetuta`; blocchi Hyrox **solo** via `getNormalizedBlocks`; titoli via `separaCodice`.
- Scrivere il catalogo: `e_staff()` **e non** `demo@fleofit.it`.
- Pagine importate con `lazy()` in `App.jsx`: il chunk `index` non deve crescere oltre ~1 KB.
- Ogni test nuovo va **visto fallire** rompendo il codice che copre.

## Review Focus

1. **Atleta senza scarpe, o con tutte ritirate** → nessuna riga nel foglio RPE, completamento identico a oggi (Task 6).
2. **Nessuna principale ma scarpe attive** (la principale è stata ritirata) → la riga compare con «Nessuna» preselezionata e non scrive niente finché non si sceglie (Task 6).
3. **Tabelle assenti** (migrazione non applicata: errore `42P01`/`PGRST205`) → card profilo, riga RPE e riga coach spariscono senza alert; `/scarpe` mostra lo stato vuoto (Task 3, 5, 6).
4. **Modello tolto dal catalogo** mentre un atleta lo usa → la scarpa resta con marca/modello copiati (Task 2 `on delete set null`, Task 3 test).
5. **km di partenza scritti male** (`"abc"`, `-5`, `"1.200"`, `"350,5"`) → `numeroKm` li normalizza o li rifiuta prima della insert (Task 3).
